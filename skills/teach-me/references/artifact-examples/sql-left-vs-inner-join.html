LEFT vs INNER JOIN

For you if you can write SELECT ... WHERE on one table and joins still feel like guessing. About 25 minutes.

By the end you will be able to:

  1. Predict the exact rows, duplicates and NULLs included, that an INNER and a LEFT JOIN return from two small tables.
  2. Write the query that finds rows with no match, and say why a WHERE filter on the right-hand table quietly undoes a LEFT JOIN.

    Placement: where should you start?

    Four questions on a tiny pet database. "Not sure" is a real answer: it routes you, it doesn't count against you.

    Part 1: Commit to a guess

    These are the two tables for the rest of the lesson. 

    SELECT c.name, o.id, o.total
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id;

    Part 2: INNER JOIN, traced by hand

    A join is a loop. For each customer, find every order whose customer_id equals that customer's id, and write one output row per match. That's all INNER JOIN does. A customer with no match writes nothing.

    Part 3: LEFT JOIN, you fill in the gaps

    LEFT JOIN runs the same loop with one change: a left-table row with zero matches still writes one row, and every column from the right table is NULL. The matched customers below are already done for you.

    Now on tables you haven't seen

    New random orders each time. Get two in a row to finish this part. A miss shows you the trace and gives you a fresh pair of tables.

    Part 4: The WHERE trap

    You want every customer, plus only their big orders. Here's the query most people write first.

    SELECT c.name, o.id, o.total
FROM customers c
LEFT JOIN orders o ON c.id = o.customer_id
WHERE o.total > 20;

    The order of operations is the whole story. The join runs first and produces the rows from Part 1. Then WHERE looks at each row. On Bo's row o.total is NULL, and NULL > 20 isn't true (it's unknown), so the row goes. LEFT JOIN protected Bo during the join; WHERE threw him out afterward.

    Move the condition into ON and it becomes part of the matching instead:

    LEFT JOIN orders o ON c.id = o.customer_id AND o.total > 20

    Part 5: Build the "no orders" query

    Goal: list the customers who have never ordered. Assemble the query, run it, and the page compares your result to the goal.
