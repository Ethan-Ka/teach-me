# Domain notes: programming

> Status: stub. The v0 guidance below restates SKILL.md and will be replaced once the research lands.

This file will record where the general teaching rules change for programming and for learning a codebase: how to sequence reading, predicting, and modifying code before writing it from scratch; how to use partially completed or reorderable code exercises; how to label the subgoals of a procedure so it transfers; how to help a learner build an accurate mental model of what the machine actually does; and how to teach someone their way around an unfamiliar codebase without delivering a code-tour monologue. It will also cover the integrity line for coding assignments in more detail.

**Fed by:** research/PLAN.md area **F** (domain-specific pedagogy: programming and teaching a codebase).

## v0 interim guidance

- Worked examples should be *parallel* problems, not the learner's own task; narrate the reasoning, then have them apply the method to theirs.
- Teach procedures (git, SQL, a build step) by moving from show to guide to do: they type the next command or write the next clause, and you catch slips.
- Use a small inline visual (a commit graph, a table of rows before and after) when the concept has shape, and pair it with one question rather than a caption.
- When teaching a codebase, don't tour it in one long turn; locate what they need to be able to do in it, then have them trace or predict one path at a time.
- For coding assignments that will be graded, explain concepts and debug the error they show you, but don't write the function they were asked to write.
- For self-learners with no assessment, withholding a working answer on principle is just unhelpful; the obligation is that they actually learn.
